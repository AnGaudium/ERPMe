# Accounting and inventory core modeled on SAP

The accounting and inventory core follows SAP's long-proven model: S/4HANA for the data model, Business One for the leanness of a first release, with no company-size limit (author, 2026-11-19). Learn the concepts and the organization; do not copy SAP documentation and do not use SAP trademarks in the product. Learning from ERPClaw (an open ERP designed for agents, built ERPNext-style) was considered and rejected: its source code showed the ledger and inventory core are not correct enough (amounts stored as strings, original lines mutated on cancellation, no revaluation after backdated documents, sales returns received at selling price).

| Concept | Applied as | Why |
| --- | --- | --- |
| Document principle | Every posting is a document with header and lines. No deletion, no edit; corrected by a correction document that refers to it, or, for internal documents only, by a reversal document; both pass the same period checks as any document | Already [Principle 5](02-principles.md) |
| Universal journal | One journal-line table carrying every analytical dimension and amounts in several currencies. Canonical dimension list: company, branch, account, partner, item, warehouse, cost center, project, salesperson; the final list is in [ADR-0014](../adr/0014-universal-journal.md). AR/AP subledgers and inventory value are views over this table | Subledgers reconcile to the GL by construction, not by reconciliation |
| Material and accounting documents | Quantity movements are material documents, values are accounting documents, written in the same transaction. Zero or one accounting document per material document; value-only accounting documents (e.g. revaluations) have no material document | Inventory and GL never drift |
| Several currencies per line | Transaction currency, company currency, optional group currency. Every journal entry balances in each transaction currency, in company currency and in group currency. Rounding differences from conversion go to a rounding line on a defined system account (DS-02 and DS-06 decide which) | Foreign-invested companies report to a parent |
| Two-tier chart of accounts | A fixed system chart in the core and an operational chart per company; each operational account points to exactly one system account (many-to-one) | Core, agents, management reports and consolidation work only with system accounts; companies detail freely. Same pattern as D365 F&O and SAP |
| Automatic account determination | Transaction key (inventory posting, offsetting entry, GR/IR clearing, price difference, cost of goods sold…) × item valuation class × valuation area → operational account. The valuation area is the warehouse or the company, per the company's costing policy. Non-inventory keys (revenue, AR/AP reconciliation, tax, FX) use other determinants (partner reconciliation account, tax code, item group), defined in DS-08 | Every automatic posting has one deterministic source of accounts |
| Movement types | A configuration table decides whether a stock movement increases or decreases stock, how quantity and value update, and which transaction keys apply | Purchase receipt, sales issue, transfer, assembly issue and return are configuration, not separate code |
| GR/IR clearing account | Goods receipt credits the clearing account; the invoice clears it; price differences go to inventory value or a price-difference account | Three-way match on both quantity and price |
| Price control per item | Phase 1: the preliminary price is the previous costed period's actual average price; for a new item, or when the previous period is not yet costed, the latest receipt price. Receipt-versus-issue differences stay in inventory until period-end costing. (After Phase 1) Standard price and moving-average price control | Valuation during the period: simulation, below-cost warnings, margin |
| Period-end actual costing | At period end compute the actual periodic unit cost, solving all warehouses (and BOM levels, with the production core of Phase 1) together, then revalue inventory and COGS | This is VAS periodic weighted average; the existing costing engine maps onto it |
| Delivery costs and subsequent debits | If the cost arrives in the same open period, it is added to the receipt value before period-end costing. If it belongs to an earlier, closed period, it is posted in the current period and allocated by the quantity each consumer took: stock on hand, transfers to other warehouses, COGS, production | Landed cost stays correct even when goods are partly sold |
| Posting periods | Open and close per company and per account type; special periods for year-end adjustments | Complements the three period states |
| Open-item FX revaluation | Revalue each unpaid receivable and payable item; cash, bank and loan balances are revalued at balance level. How the difference is booked is set by the localization package | Matches the AR/AP subledger and each country's rules |
