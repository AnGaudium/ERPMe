# Design validation lab (2026-11-14)

The author asked for a project database on the build server, to test the design's data flows before any product code exists. This folder records what the lab ran and what it found.

The lab code is design evidence, not product code. It follows none of ADR-0022's conventions and is never imported by the product.

## Setup

- PostgreSQL 18, the version ADR-0006 and ADR-0022 require, in a separate container bound to localhost.
- Python with psycopg. The connection string comes from `NATIVEFLOWS_LAB_DSN`, and the password from `PGPASSWORD`.
- Each SQL scenario loads `00_stubs.sql` and then DS-06, unchanged and in file order, into a clean schema.
- `load_all.py` loads every DDL file of `design/` together: `00_stubs.sql` without the stub tables a DDL file now defines, `btree_gist` and `pg_trgm` in schema `nativeflows`, and one dependency order over all files. The simulation uses it.
- The standard load for `t01` to `t10` and `t13`, which run without `--load`: on a fresh database, the extensions, `00_stubs.sql` and the ordered DS-20, DS-56 and DS-06 statements go through one session, because the stubs set `search_path`:

  ```bash
  cat design/DS-20-master-data.sql design/DS-56-product-configuration.sql design/DS-06-universal-journal.sql > /tmp/std.sql
  { echo "CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE EXTENSION IF NOT EXISTS btree_gist;"; cat reviews/2026-11-14-design-validation/lab/00_stubs.sql; python3 reviews/2026-11-14-design-validation/lab/load_ds06.py /tmp/std.sql; } | psql -v ON_ERROR_STOP=1 "$NATIVEFLOWS_LAB_DSN"
  ```

- The `id` default, a lab-only stand-in for the command layer (S2 schema phase B): 87 tables gained the primary key `id` in phase B with no default, because the command layer supplies UUIDv7 IDs (ADR-0006 rule 2), and their fixtures insert without one. After the DDL, `load_all.py` and `load_ds06.py` run `lab.id_default_shim_sql()`, which gives `id` the default `uuidv7()` on those of `lab.PHASE_B_ID_TABLES` that the load defines. The design DDL never has it; fixtures that insert by position give the id themselves.
- Reloading over an already loaded database drops the old tables in batches of 40, each in its own transaction, before the stubs drop the schema, and then loads the DDL in transactions of 150 statements, so one transaction never needs more locks than `max_locks_per_transaction` allows (it failed with "out of shared memory" at about 300 tables).

What L-06 shows:
- **Linear.** One period is linear in the stock-node prices once these are quantities or constants: allocation weights, units in process, completion shares and normal capacities. Allocation by solved material cost is not linear; ADR-0035 therefore allocates by material at preliminary prices.
- **WIP across periods.** WIP is well defined across periods only when it is recorded by cost component; ADR-0035 adds `production_order_period_cost`.
- **Planned WIP.** It needs a cap, applied by solving again, when it exceeds the order's cost.
