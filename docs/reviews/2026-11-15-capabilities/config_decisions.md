# Decisions: configurable policy settings (ADR-0063), chief architect, 2026-11-15

Author direction (2026-11-15): survey best practice and follow it; keep hard locks to a minimum; make policy configurable so each customer sets it at implementation. Also: no Vietnam content at all in this work (no VN law, no VN examples, no l10n_vn edits); country packages fill neutral settings later.

Sources: holistic/research_config_autonomy.md, research_config_dataprocessing.md (ignore its VN example in R5), research_config_extensibility.md, research_config_masterdata.md (ignore section 7).

## P. Principles (new ADR-0063)

P1. One settings registry. Every policy choice is a registered setting with: key, scope (installation, regime package, company, product category, rule/artifact version), type, core default (or "none: fail closed" where ADR-0053 requires), hard bounds, direction (which values are tighter), the leaf whose `edit` changes it, and whether a change marks dependent evidence outdated. Reuse the existing settings mechanism if the design has one (find it: ADR-0053, DS-05, regime settings, company settings); extend it rather than invent a second one. A catalog `docs/catalogs/settings.csv` (or the existing equivalent) lists every setting this ADR touches, so the registry is checkable by lab.
P2. Asymmetric change path (EU AI Act Art. 14, NIST MANAGE, SOX change control): tightening is immediate by one person with the leaf; loosening is a change proposal under ADR-0043/0055 with segregation of duties (proposer != approver), effective from approval (or from a period start where the setting says so), and marks dependent auto-post / promotion evidence outdated (ADR-0059 marker). Every change writes an audit row with old, new, actor, reason.
P3. Implementation-time setup: the setup flow (ADR-0044 onboarding or the existing setup design) presents the registry grouped by area with defaults; a company starts on safe defaults; nothing silently changes behaviour on upgrade (a new setting's default reproduces today's behaviour unless that behaviour was unsafe, and then the ADR says so and raises a work item).
P4. Hard locks, kept few and each with its reason in a table: numbers only from code (Principle 13); audit trail and log-before-call; agents never submit/post/send on their own authority except the evidence-gated auto-post paths; taint persists and tainted runs write drafts only; schema-derived personal labels are never lowered; the circuit breaker cannot be turned off; no AI-written code runs without human source review; check digits and other integrity checks; error ceiling of any auto-post path never above 2% proven at 95% confidence.

## A. Autonomy (research_config_autonomy.md)

A1. Extraction value trust: accept the ADR-0057 rule 17 reading as the default; add tighten-only per-field settings `intake.trust.<doc_type>.<field>.require_confirmation`, `min_passed_rules` (default 1), `ocr_min_confidence` (0.90, bounds 0.80-0.99). Loosening below default needs extraction-mapping evidence. Hard: free text, URLs, e-mails, phones never trusted; vision values never trusted before a person confirms.
A2. LLM-originated rules feeding auto-post: setting `cash.auto_post.accept_llm_originated_rules`, company, default false. When true, approval ends the LLM contribution only if: whole reference-shaped token; rule went live on independent evidence (>= 10 suggest-mode drafts, 99% posted unchanged); approver != proposer; origin recorded; the 300-proposal evidence counts that basis. `llm_suggestion` drafts never auto-post (hard). Record in open-questions as answered by the author's direction (configurable, safe default off); the spec 03 rule 1 wording is author-owned: flag that it should say "unless the company enables ... under ADR-0063".
A3. Bank fees: new account-rule class `bank_charge`: passes the counterparty check when the line is a debit, carries a bank charge code configured for that bank account, names no third-party account. Auto-post per rule, default off; requires `amount_max` <= company setting `cash.bank_charge.auto_post_ceiling` (no core default value beyond 0 = disabled); evidence `cash.bank_charge.min_evidence_lines` (default 6, bounds 3-50) over `min_statement_months` (default 3). Hard: never when open items also match, never with two rules matching, never above the cap, never from the LLM's purpose classification. Answers "should bank fees ever auto-post": yes, configurable.
A4. Promotion/demotion thresholds: confidence-bound based. Settings `auto_post.max_error_rate` (default 1%, bounds 0.1%-2%) with required error-free cases ~ 3/rate at 95%; `artifacts.<kind>.max_window_days` (up to 365); small companies get a longer window, not a lower bar; suggest-mode minimums (50 backtest, 30 live) are settings with bounds. Demotion judged on >= 30 decisions; any confirmed wrong auto-post suspends auto-post at once (hard).
A5. Agent triggers: per agent type version, `agents.<type>.wake_up_mode.<kind>` = always | by_rule | off, default always (today's behaviour, so upgrade changes nothing). First configurable kinds: quotation `inbound_message_matched`, purchase invoice `supplier_invoice_received`. Conditions use trusted metadata only (mailbox, channel, partner matched by address, branch, source). Narrowing/off by one person; widening by proposal. Hard: no agent wakes an agent; rules never widen tools, scope, budget or taint handling; no triggers on approval, posting or send events. This replaces ADR-0058 rule 7's "no rule hands items to people" path for these kinds.
A6. Drift for agent types: `agents.<type>.drift_action` = signal | pause_new_runs | demote_to_shadow, default signal. Hard: drift that outdates auto-post evidence always suspends auto-post. Artifacts keep automatic demotion.
A7. Analysis agent examples: `artifacts.analysis.min_verified_examples` (default 30, bounds 0-500) and `artifacts.analysis.allow_synthetic_only_promotion` (default true); answers show "evaluated on the synthetic suite only" while below the minimum; shadow evaluation starts automatically at the minimum.

## D. Data processing (research_config_dataprocessing.md)

D1. Personal vision seat: allowed through a `data_processing_permission` row (company, data class, seat class, provider, region, optional purposes), default none (seat off). Provider registry gains `retention_days`, `abuse_review`, `trains_on_customer_data` (must be false), `terms_ref`. Changes by four-eyes proposal under a new leaf `data_processing` (under `agent`). A provider change of region or terms suspends the permission. Hard: no tools on the seat; routing_switch stays the kill switch; no sensitive personal data class in Phase 1.
D2. Field-level personal values: one gate on every request; without a permission, values become placeholders or shape masks; a step that needs them ends `routing_blocked`. Default placeholders. Upgrade impact stated (companies relying on today's behaviour need permissions; raise a work item at upgrade). Optional `data_processing.never_send_fields` (narrow only). Hard: labels from schema never lowered; log before call.
D3. Tainted catalog reads: registry attribute `tainted_projection`; company setting `agents.tainted_reference_reads` = literal | declared_projections, default declared_projections; first instance `ResolveItemCandidates`; bounds 20 candidates per call, calls-per-run cap. Hard: never prices, costs, stock, partner columns, personal or free text; run stays tainted. Answers the open question.
D4. Analysis question text stays `personal`; `analysis.pseudonymize_known_subjects` company, default on.
D5. Cross-border: widen the core schema of the data-processing policy per data class (model processing allowed, cross-border rule, assessment kind and deadline, allowed countries, max provider retention, no-training requirement, package-declared exemptions). No core default (fail closed, as ADR-0053). Packages may only tighten core floors. No country content in this ADR.

## E. Extensibility (research_config_extensibility.md)

E1. L3: Phase 1 ships only the `extension_point` registry (typed input/output, code default, ceilings); no runtime. After Phase 1: WebAssembly with fuel metering; `extensions.wasm_enabled` (installation, default false); per company and point `max_fuel`, `max_memory_bytes`, `deadline_ms` with ceilings; gates as research. Hard: no I/O, clock, randomness; metering always on; no extensions at approval, posting, rights or settings decisions.
E2. Levels 1 and 3 in Phase 1: yes, as ADR-0058 has them. New settings `automation.dispatch_paused` (pause immediate, resume by proposal), `automation.max_active_rules` 200 (1-1000), `automation.replay_window_days` 30 (7-90), `automation.replay_min_events` 20. Flag to the author: spec 16 level split 1a/1b and spec 10 "no rule language; structured tables and rules" (author-owned text; open question with proposed wording). Optional artifact export/import as draft: include, flagged.
E3. Circuit breaker: `breaker_failures` 5 (1-50), `breaker_window_minutes` 60 (5-1440), `breaker_consecutive` 20 (3-200, >= failures); per-rule overrides in the rule version; flood guard `automation.max_executions_per_rule_per_hour` 500 (10-10000) recording `rate_limited` (not a failure). Hard: breaker cannot be off; failure definition fixed; re-enable by a person; depth cap stays a constant.

## M. Master data and narrative (research_config_masterdata.md, sections 1-6 only)

M1. Product codes: `master_data.product_code.assignment` = sequence | manual | sequence_or_manual, prefix source, pad width; company with per-category override; default sequence (gappy). Hard: unique per company, never reused, immutable once referenced, no meaning read from the prefix. Answers the open question.
M2. Unit names: keep ADR-0056 rule 2; add regime-package settings `documents.unit_name_max_length` (empty in core), unit name source, `documents.e_invoice_unit_code_scheme` (UN/ECE Rec 20/21 default) with a package mapping file. Hard: a statutory output never truncates silently. Answers "where unit names live".
M3. Purchase return value: `movement_type.purchase_return.valuation` = document_value | current_cost, `include_landed_cost`, reporting, variance account; default document_value, landed cost included; change only from a period start. Hard: GR/IR clears at PO value, differences go to a named account. Answers the open question (generic; the existing regime-setting prefix stays).
M4. Narrative: `analysis.narrative_mode` = facts_only | claim_plan | free_prose; installation sets the maximum, company may only lower; default claim_plan; free_prose stays unavailable in Phase 1 and unlocks only when evaluation shows >= 80% acceptance and zero unbacked numbers or claims (still prose labelled model-written and dropped on any unbacked number).
M5. Barcodes: day 00 policy per AI = last_day | first_day | reject (GS1 default last day for expiry-type); `best_before_fills_expiry` default FALSE, per product category (changes the ADR-0061 interim; note on ADR-0061); `unknown_ai_policy`; per scanner profile lost-separator stop.
M6. Near-duplicate invoices: date window 7 (0-90), amount tolerance 1 minor unit (0-100), number normalization digits_only, outcome review with payment held. Hard: the exact key cannot be switched off and applies on every channel; never auto-deleted.
